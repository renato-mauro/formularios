O formulário (.form)

Exemplo

Cada linha do arquivo é uma linha do formulário: o texto já parece o formulário. Uma página (pages/clientes.form) que inclui dois componentes, um deles duas vezes: 

-Cadastro de Clientes
--Dados Pessoais{pessoais}
+pessoa
--Endereço Residencial{residencial}
+endereco
--Endereço Comercial{comercial}
+endereco
--Sexo*
(M) Masculino
(F) Feminino
( ) Prefiro não informar
--Observações{obs}
______________________________________________
______________________________________________
[ ] Aceito os termos de uso{aceite}*

O componente components/pessoa.form (componente não tem título):

Nome*: ______________________________   Salário: R$ __________
CPF*: 999.999.999-99   Nascimento*: dd/mm/aaaa

E o components/endereco.form:

Cidade: _____________   Estado: @estados   CEP: 99999-999

O .form só declara a estrutura, o tipo de cada campo (pela máscara) e o que é obrigatório. Não há comentários, regras, validações extras nem botões: isso fica no JS. A página acima sai com um botão, Enviar; outros vêm das ações.

No editor, Ctrl+Espaço sugere o que cabe onde está o cursor: depois de Rótulo: , os tipos de campo e as listas; depois de +, os componentes do projeto; numa linha vazia, seção, seção com componente, opções e caixa de marcação.

Páginas e componentes

O projeto tem duas pastas fixas, as duas primeiras listas à esquerda: Páginas (pages/), os formulários que viram páginas, e Componentes (components/), formulários que só entram nas páginas, como um endereço usado em vários lugares. Um componente é escrito como qualquer formulário (campos, seções, opções), mas sem título: o título vem da seção onde ele entra. 

--Endereço Residencial{residencial}
+endereco
--Endereço Comercial{comercial}
+endereco
  • O componente entra sozinho numa seção, como o texto longo de Observações: a linha +componente logo abaixo de --Título{nome}, e nada mais. A seção dá o título e o nome; os campos do componente ficam direto nela. No JSON: "residencial": { "cidade": …, "cep": … }.
  • A seção termina no +: o que vem depois volta à seção de cima, e ela não recebe subseções.
  • O componente entra como ele é: os obrigatórios valem como estão lá. Regras como “pelo menos um dos endereços” ficam no JS.
  • Um componente pode incluir outros. Componente que não existe, inclusão circular (a → b → a) ou erro dentro do componente aparecem na linha da inclusão; clique no problema para abrir o componente onde está o erro.
  • Renomear um componente atualiza as linhas +nome das páginas e os imports do JS. O nome do arquivo é o nome do formulário: clientes.form gera clientes.html, clientes.js e <form id="clientes">.
  • Uma página pode não ter campos próprios: só o título e as seções dos componentes. Com um componente aberto, a pré-visualização mostra o componente sozinho.

Sem decorar nada: o botão + Campo, na barra do editor, abre o assistente. Você escolhe o tipo, o rótulo, o nome no JSON, se é obrigatório e os parâmetros (tamanho, dígitos, máscara, lista, opções, largura), vê a linha que vai entrar e insere. O campo entra numa linha nova depois da do cursor, ou ao lado dos campos dela; Ctrl+Z desfaz. Numa lista, os itens podem vir da coleção, e o arquivo vem junto.

Título e seções

  • -Cadastro de Clientes: o título da página, na primeira linha (componente não tem título). Sem {nome}: o nome do formulário é o do arquivo (cadcli.form → cadcli.html, cadcli.js e new Form('#cadcli')); renomear o arquivo renomeia tudo.
  • --Texto abre uma seção e ---Texto uma subseção dentro da última seção. No máximo três níveis (---- é erro) e sem pular nível (de - direto para ---).
  • Cada seção vira um <fieldset> e um nível no JSON, com o nome das chaves (--Dados Pessoais{pessoais} → "pessoais": { … }) ou do texto.
  • Os campos ficam na seção aberta mais recente. Depois de abrir uma subseção não se volta à seção de cima: para pôr campos de novo no nível de cima, abra outra seção --.
  • O espaço depois dos hífens é opcional: --Dados = -- Dados.

Linha de campos

Rótulo{nome}*: especificador   Outro: especificador{N}   …
  • O rótulo termina em :, tem ao menos uma letra e fica sempre acima do campo.
  • * = obrigatório. Só é cobrado no envio (form.validate()), não enquanto a pessoa digita.
  • {nome} dá o nome do campo; sem ele, o nome vem do rótulo (veja Nomes). A forma usual é Endereço{logradouro}*:; o * também pode vir antes das chaves.
  • O espaço entre : e o especificador é opcional: Nº*:________.
  • {N} colado no fim do especificador fixa a largura em N colunas (de 1 a 12): Nome: ______{6}, CPF: 999.999.999-99{3}, Nascimento: dd/mm/aaaa{2}. Veja Larguras.
  • Até 12 campos por linha. Um especificador que não está na tabela abaixo é erro, com linha e coluna na lista de problemas.

Máscaras e tipos

O especificador define o tipo do campo, a máscara e a validação embutida. É reconhecido nesta ordem:

email__________e-mail (confere o formato)texto

  • Máscara posicional: 9 (ou 0) é dígito, A é letra e * é letra ou dígito; o resto é literal, inserido sozinho enquanto se digita.
  • Só com dígitos, 9 e 0 mudam o tipo: 999 é número, 000 é código (texto com zeros à esquerda). Misturar os dois (0099) é erro. Com literais, tanto faz: 00000-000 também é CEP.
  • Inteiro, decimal e moeda aceitam negativo. Limites ficam fora do .form: data-min/data-max no HTML ou field.min/field.max no JS.
  • Campo vazio sai null. CPF, CNPJ, CEP, telefone e máscaras posicionais saem com a pontuação; para tirar, use a opção literals do Form no JS.

Listas @nome

Estado: @estados        ← divide a linha com os outros campos
Estado: @estados{3}     ← sempre 3 colunas (de 1 a 12)
  • Vira um <select> só com “Selecione…”. As opções vêm do JS: form.list('estados', …) na página, parte.list('estados', …) num componente.
  • Com um arquivo de dados estados.json no projeto (seção Dados, à esquerda), o JS inicial já lê o arquivo. Formato: [{ "value": "SP", "label": "São Paulo" }] ou ["SP", "RJ"].
  • Listas prontas: o botão Coleção, em Dados, importa estados do Brasil, regiões, países, meses, dias da semana, estado civil, escolaridade, grau de parentesco, tipo sanguíneo, tipos de logradouro e sim/não. Cada uma vira um arquivo do projeto com o mesmo nome (paises.json serve a @paises), que você pode editar.
  • Largura: sem {N}, a lista divide a linha como um campo de 8 caracteres; sozinha, ocupa a linha inteira. Com {N}, fica com N colunas.
  • O nome do campo vem do rótulo (estado), não da lista.

Opções (escolha única e múltipla)

--Sexo*                     --Interesses
(M) Masculino               [ESP] Esportes
(F) Feminino                [MUS] Música
( ) Prefiro não informar
  • Sempre numa seção própria, uma opção por linha. O título da seção é a pergunta; * nele = obrigatório.
  • (valor) = escolha única (rádio). [valor] = seleção múltipla: no JSON, uma lista (["ESP", "MUS"]). Os dois não se misturam na mesma seção.
  • Sem valor (( ), [ ]), o valor é o próprio texto: "Prefiro não informar".
  • A seção inteira é um campo só: não cria nível no JSON. "sexo" fica no objeto da seção de cima.
  • Termina na primeira linha de outro tipo; o que vem depois volta à seção de cima. Numa seleção múltipla, [ ] Texto{nome} ou [ ] Texto* já é uma caixa de marcação isolada.

Texto longo

--Observações{obs}
______________________________________________
______________________________________________
______________________________________________
  • Seção com linhas só de _: uma caixa de texto com tantas linhas de altura quantas foram escritas (aqui, 3). Ocupa sempre a largura toda.
  • O título é o rótulo (* nele = obrigatório). Como as opções, é um campo só e não cria nível no JSON.

Caixa de marcação

[ ] Aceito os termos de uso{aceite}*
  • [ ] seguido do texto, fora de seção de opções. O texto fica ao lado da caixa (a única exceção ao “rótulo acima”).
  • No JSON, true ou false. Com *, precisa estar marcada no envio.
  • Pode dividir a linha com outros campos: Nome: ____________ [ ] Ativo.

Botões

  • O .form não tem botões: botão é comando, e comando fica no JS da página. A página sai com um só, Enviar.
  • Cada form.action(nome, …) registrado no JS da página vira um botão, na ordem do registro: o primeiro é o principal (azul); os outros, secundários. Com ações registradas, o Enviar só aparece se houver uma ação enviar. Veja Ações.
  • Componentes não têm botões nem ações.

Nomes e JSON

  • Sem chaves, o nome é o texto em minúsculas, sem acentos, com _ no lugar do que não é letra nem número: Data de Nascimento → data_de_nascimento, E-mail → e_mail, Nº → numero.
  • Nomes repetidos na mesma seção ganham _2, _3 (e um aviso). Em seções diferentes, podem se repetir: cep em residencial e em comercial.
  • No JS da página, o nome é o caminho completo, com as seções e inclusões: pessoais.nascimento, residencial.cep. Só 'nascimento' não encontra o campo. No JS de um componente, os nomes são relativos à parte dele ('cep'; veja O JS do componente).

O exemplo do início gera este JSON (veja o seu com Coletar JSON, na pré-visualização):

{
  "pessoais": {
    "nome": "Maria", "salario": 1234.56,
    "cpf": "529.982.247-25", "nascimento": "1980-05-17"
  },
  "residencial": {
    "cidade": "São Paulo", "estado": "SP", "cep": "01310-100"
  },
  "comercial": { "cidade": null, "estado": null, "cep": null },
  "sexo": "F",
  "obs": null,
  "aceite": true
}

Larguras

  • Cada linha de campos ocupa as 12 colunas da grade, divididas na proporção do tamanho com que cada campo foi escrito: o número de _ ou de caracteres da máscara (dd/mm/aaaa = 10, CPF = 14). Caixa de marcação: o texto + 4. Lista: 8.
  • Endereço: ________________________ Nº: ________ Complemento: ________ → 7 + 3 + 2 colunas.
  • Largura fixa: qualquer especificador com {N} no fim fica com N colunas; o resto da linha é dividido entre os outros campos. Nome: ______{6} CPF: 999.999.999-99 → 6 + 6 colunas; Telefone: (99) 99999-9999{4}, Salário: R$ ____{3} e Estado: @estados{2} também valem. As larguras fixas de uma linha somam no máximo 12.
  • Cada campo tem pelo menos 1 coluna, então um campo curto ao lado de campos longos fica estreito. Para alargar, escreva mais _, use {N} ou passe o campo para outra linha.
  • Em telas estreitas, cada campo ocupa a linha inteira.

O JS

O JS da página

O comportamento fica no JS, a aba ao lado da especificação: o JS da página (pages/clientes.js) e o de cada componente (components/endereco.js). Enquanto você não mexe nele, o JS é gerado a partir do .form. Ao editar, ele passa a ser seu; Voltar ao JS inicial descarta as mudanças. 

import { Form, utils } from './forms.js';

const form = new Form('#clientes');   // o nome do arquivo

// As ações viram os botões.
form.action('enviar', async ({ form, data }) => { … });

// Chama o JS dos componentes; liga máscaras, listas e botões.
await form.ready();
  • A página cuida do que é dela: as ações (os botões), as listas e regras dos campos que estão nela e as regras que juntam partes. O que é de um componente fica no JS do componente.
  • A página não importa nem chama o JS dos componentes: o form.ready() faz isso sozinho, uma vez para cada seção de componente. O JS inicial lista num comentário quem é chamado e com que parte.
  • Registre tudo antes de await form.ready(). Um erro antes dele interrompe o JS, e a página fica sem máscaras, listas e botões. A lista de problemas avisa quando isso acontece.
  • Os campos são sempre chamados pelo nome completo, com as seções e inclusões: pessoais.cpf, não cpf.
  • O editor ajuda a escrever. Ao digitar form., aparecem os métodos. Dentro das aspas, aparecem os nomes deste formulário: campos em form.field(' e { name: ', partes em form.scope(', listas em form.list(', eventos em form.on(' e arquivos de dados em fetch(' e loadJson('. Ao digitar utils., aparecem as funções prontas. Numa linha vazia, Ctrl+Espaço oferece instruções prontas (form.action, form.list, validator, calcField…).
  • Opção do construtor: new Form('#clientes', { literals: { cpf: false } }) faz o CPF sair sem pontuação no JSON ("52998224725"). Vale por tipo (cpf, cnpj, cep, phone e mask, as posicionais); literals: false vale para todos. setData() aceita os dois formatos.

O JS do componente

É uma função que recebe a parte do formulário onde o componente foi incluído. O form.ready() da página a chama sozinho, uma vez para cada seção do componente; dentro dela, os nomes são relativos: 'cep' é o residencial.cep numa chamada e o comercial.cep na outra. 

// components/endereco.js
import { utils } from '../forms.js';

export default function endereco(parte) {
  parte.list('estados', utils.loadJson('./estados.json'));
  parte.validator({ name: 'cep' },
    (valor) => valor !== '00000-000' || 'CEP inválido.');
}
parte.list, validator, calcField, on, maskTypecomo no form, com nomes relativos; { selector } e list valem só dentro da parte (a lista da parte vence a do formulário)
parte.field(nome), fields(alvo), reloadList(alvo)sem alvo, todos os campos da parte
parte.validate()valida só a parte
parte.getData()
parte.setData(json)		o objeto da parte no JSON / preenche só a parte
parte.clear(), readOnly(flag)só os campos da parte
parte.scope(nome)uma parte dentro desta (a seção de um componente incluído por este)
parte.prefixonde a parte está ('residencial')
  • A parte não tem ações (nem ready e messages): os botões são da página.
  • Um componente que inclui outro também não chama o JS dele: o form.ready() chama todos, de fora para dentro.
  • Se o JS não carrega, não exporta a função ou dá erro, aparece na lista de problemas com o arquivo e a linha; o resto da página continua funcionando.
  • Com o componente aberto, a pré-visualização chama a função com o formulário inteiro como parte, para testar o componente sozinho.

Alvos

validator, on, validate, reloadList e fields recebem um alvo, sempre explícito: 

{ name: 'pessoais.cpf' }                        // um campo
{ name: ['residencial.cep', 'comercial.cep'] }  // vários campos
{ selector: '[data-mask="dd/mm/aaaa"]' }        // seletor CSS
  • Não há curingas. Um nome que não existe gera um aviso com o nome completo sugerido ("cpf" → "pessoais.cpf"), e o alvo não tem efeito para esse nome.
  • O seletor é procurado dentro do formulário, na hora do uso: vale também para mudanças feitas à mão no HTML.

Listas

form.list('estados', async ({ form, field, data }) => {
  const resposta = await fetch('./estados.json');
  return resposta.json();
  // [{ value: 'SP', label: 'São Paulo' }, …] ou ['SP', 'RJ']
});
  • O provedor devolve um array (null = lista vazia). Esquecer o .json() é o erro mais comum, e a lista de problemas avisa: “recebeu Response; faltou .json()?”.
  • É chamado a cada ready() e reloadList(), sem cache. data é o JSON do formulário naquele momento e field é o campo da lista.
  • Sem form.list, o <select> fica como está no HTML.
  • Para só ler um arquivo, há um provedor pronto: form.list('estados', utils.loadJson('./estados.json')) (funções prontas).

Lista que depende de outro campo, no JS de um componente com Estado: @estados e Cidade: @cidades (buscarCidades é uma função sua). Cada inclusão tem a sua parte, então a cidade segue o estado do mesmo endereço: 

parte.list('cidades', async () => {
  const uf = parte.field('estado').value;
  return uf ? buscarCidades(uf) : [];
});
parte.on('change', { name: 'estado' },
  () => parte.reloadList({ name: 'cidade' }));

Ações (os botões)

form.action('enviar', async ({ form, data, button }) => {
  if (!form.validate({ focus: true }).valid) return;
  const r = await fetch('/api/clientes', {
    method: 'POST', body: JSON.stringify(data),
  });
  // 422: o servidor devolveu [{ field, message }]
  if (r.status === 422) return { errors: await r.json() };
});
form.action('cancelar', () => history.back(),
  { label: 'Voltar' });
  • Cada ação vira um botão, na ordem do registro: aqui, Enviar (o principal) e Voltar. O texto vem de label ou do nome (gravar_rascunho → “Gravar rascunho”). Sem nenhuma ação, a página mostra só Enviar.
  • Clicar num botão não valida nada sozinho: chame form.validate() quando quiser. data é o JSON no momento do clique.
  • Enquanto o callback não termina, os botões ficam desabilitados.
  • Devolver { errors: [{ field: 'pessoais.cpf', message: '…' }] } mostra esses erros nos campos (útil para a resposta do servidor).
  • Uma exceção no callback vira o evento fm:error. Clicar no Enviar sem form.action('enviar', …) gera um aviso.

Validadores

form.validator({ name: 'pessoais.nascimento' }, (valor) => {
  const hoje = new Date().toISOString().slice(0, 10);
  return valor <= hoje || 'A data não pode ser futura.';
});
form.validator({ selector: '[data-mask="R$"]' },
  (valor) => valor >= 0 || 'Informe um valor positivo.');
  • Devolva true (válido) ou o texto do erro. Só validadores síncronos. O 2º parâmetro traz { form, field, data }.
  • valor é o valor do JSON (data "1980-05-17", moeda 1234.56). Com o campo vazio, o validador não é chamado: vazio é assunto do *.
  • Vários por campo. A ordem é obrigatório, depois a máscara, depois os validadores na ordem em que foram registrados. Para no primeiro erro e mostra só ele.
  • Rodam ao sair do campo (depois do primeiro erro, a cada tecla) e em form.validate().

Validação para todos os campos de uma máscara (pisValido é uma função sua). Aceita também literals: 

form.maskType('999.99999.99-9', {
  validate: (valor) => pisValido(valor) || 'PIS inválido.',
});

Campos calculados

form.calcField('pedido.total',
  ['pedido.quantidade', 'pedido.preco'],
  (qtd, preco) => (qtd && preco ? qtd * preco : null));
  • 1º parâmetro: o campo calculado. 2º: as dependências. 3º: a função, que recebe os valores das dependências (os do JSON), na mesma ordem, e devolve o valor do campo.
  • O campo fica somente leitura. É recalculado em ready(), quando uma dependência muda e depois de setData().
  • Pode depender de outro campo calculado; um ciclo é erro.
  • Um nome que não existe é erro: o JS para ali (e com ele as máscaras). A mensagem sugere o nome completo.
  • Idade, prazos, somas e médias já têm função pronta, que vai direto no 3º parâmetro: calcField('idade', ['nascimento'], utils.dateDiffYears).

Funções prontas (utils)

Vêm do runtime junto com o Form e servem direto como provedor de lista ou como função de calcField. A página importa { Form, utils } de './forms.js'; o componente, { utils } de '../forms.js'. O JS inicial já vem com o import. 

parte.list('estados', utils.loadJson('./estados.json'));
parte.calcField('idade', ['nascimento'], utils.dateDiffYears);
form.calcField('prazo', ['inicio', 'fim'], utils.dateDiffDays);
form.calcField('total', ['valor1', 'valor2'], utils.sum);
loadJson(url)provedor de lista que lê o JSON (URL relativa à página); url pode ser ({ data }) => url
dateDiffYearsanos completos (trunca)
dateDiffYearsFracanos com a fração do ano em curso
dateDiffMonthsmeses completos (trunca)
dateDiffMonthsFracmeses com a fração do mês em curso
dateDiffDaysdias
sum, avgsoma, média
min, maxmenor, maior
  • Datas: com uma dependência, a diferença é até hoje; com duas, é fim − início (negativa se o fim vier antes). Faltando uma das datas, o resultado é null; a segunda vazia não vira hoje.
  • O ano e o mês vencem no dia de mesmo número. Se ele não existe no mês (29/02, dia 31), vencem no dia seguinte (Lei 810/1949): quem nasceu em 29/02/2000 fez 1 ano em 01/03/2001.
  • A fração é a parte já decorrida do ano ou do mês em curso, em dias: de 01/01 a 02/07/2025 são 182/365.
  • Números: sum, avg, min e max usam só o que estiver preenchido. Basta um valor: sum(10, null) é 10 e avg(4, null, 8) é 6. São null só quando não há nenhum.
  • Também valem no seu código, com mais argumentos ou arrays: utils.sum(itens.map((i) => i.valor)).

Dados e estado

Eventos

const parar = form.on('change', { name: 'residencial.cep' },
  ({ value, old }) => console.log(old, '→', value));
form.on('invalid', ({ errors }) => console.log(errors));
parar();   // deixa de escutar
  • form.on(evento, alvo, (detail, e) => …). O alvo é opcional e só filtra o change, o único evento de um campo. Devolve a função que cancela a escuta.
  • São CustomEvent disparados no <form>, com o prefixo fm:, e sobem pela página: form.element.addEventListener('fm:change', (e) => e.detail) também funciona, inclusive fora do JS da página.
EventoQuandodetail
readyno fim de form.ready(){ form }
changeo valor de um campo mudou: ao sair do campo, ao escolher numa lista, opção ou caixa, ao atribuir field.value, depois de setData() e clear() e quando um campo calculado é recalculado{ field, value, old }
actionclique num botão, antes do callback; e.preventDefault() cancela a ação{ action, data }
invalidvalidate() ou showErrors() com erros{ errors }
errorexceção num provedor de lista, numa ação, num validador ou num calculado; lista que não devolveu array; botão sem ação{ error, source }, com source 'list', 'action', 'validator' ou 'calc'

Exemplo: pedir confirmação antes de cancelar.

form.on('action', ({ action }, e) => {
  if (action !== 'cancelar') return;
  if (!confirm('Descartar as mudanças?')) e.preventDefault();
});

Na pré-visualização

  • O JS da página e o dos componentes rodam com o runtime de verdade, um instante depois que você para de digitar. Um componente aberto aparece sozinho, sem botões.
  • utils.loadJson('./estados.json') e fetch('./estados.json') leem o arquivo de dados do projeto.
  • Erros e avisos do JS aparecem na lista de problemas, embaixo do editor, com o arquivo e a linha (components/endereco.js 3: …). Clique para ir até ela, mesmo que seja em outro arquivo.
  • Validar chama form.validate() e Coletar JSON mostra form.getData(). Ao clicar num botão do formulário, aparece o JSON da ação.
  • Estrutura mostra os dados do formulário: cada campo com o caminho no JSON (residencial.cep), o tipo, o valor no JSON (string, number, boolean…), se pode ficar nulo (vazio vira null; os obrigatórios são “não nulo”) e os detalhes, e um exemplo do JSON. Serve para quem vai receber os dados.
